## 1. 知识依赖声明

本文档定义的优化建议不是凭空生成的。生成优化建议时需要引用以下知识来源：

| 知识来源 | 用于生成什么 |
|---------|------------|
| **规则 1（分类体系）** | 识别报错的业务场景上下文（是什么任务、什么模块）|
| **规则 2（体验评估标准）** | 确定优化方向（时机/形式/文案/交互哪里违规）|
| **业务知识库**（`01体验评估阶段/业务知识库/`）| 为文案建议和帮助中心文章提供业务规则解释、正确操作指引 |
| **历史优化案例库** | 同类报错的优化方式参考和成效基准 |

**引用规范**：帮助中心文章中涉及业务规则解释的段落，需标注引用了哪条业务知识。格式：`（参考：业务知识库 / {模块名} / {知识点}）`。

---

## 2. 输出格式总览

优化建议按四个维度输出，每维度统一为以下格式：

```
【{维度}优化建议】

当前问题：{一句话描述当前存在的问题}
建议方案：{具体的修改建议}
依据：{引用的评估标准或业务知识}
预期效果：{优化后用户能感知的改善}
```

## 3. 文案建议格式

### 3.1 文案格式类型与模板

| 格式类型 | 适用场景 | 文案模板 | 示例 | 语气原则 |
|---------|---------|---------|------|---------|
| **权限告知型** | 操作/数据权限不足 | 暂无【{功能名称}】的{操作/查看}权限，请联系{管理员角色}开通 | 暂无【员工档案查询】的查看权限，请联系 HR 管理员开通 | 中性告知，不责备用户；"开通"比"分配"更友好 |
| **数据占位型** | 数据权限不足/记录不存在 | [图标] 暂无此{数据范围}的查看权限。如需获取权限，请联系{管理员角色} | [空状态图标] 暂无华东区数据权限。如需获取权限，请联系区域管理员 | 不暗示错误，仅说明当前状态 |
| **状态提示型** | 已锁定/结账/冻结 | 当前{期间}已{状态}，{数据}不可编辑。如需修改，请联系{角色} | 当前 2026 年 3 月已结账，财务数据不可编辑。如需修改，请联系财务负责人 | 说明原因+解决方案，不阻塞页面 |
| **参数校验型-空值** | 表单必填为空 | 请填写{字段名} | 请填写成员姓名 | 简洁直接，不用"您"、不感叹号 |
| **参数校验型-格式** | 日期/编码/长度错误 | 请输入正确的{格式说明}，如 {示例} | 请输入正确的日期格式，如 2026-01-01 | 给出正确示例，帮助用户修正 |
| **参数校验型-长度** | 字段超长 | 最多可输入{max}个字符，当前已输入{current}个 | 最多可输入 50 个字符，当前已输入 68 个 | 告知限制和当前值，方便用户调整 |
| **存在性校验型-重复** | 名称/编码重复 | "{名称/编码}"已被使用，请更换 | "ACCT-001"已被使用，请更换 | 直接告知冲突，可附带被谁使用 |
| **存在性校验型-不存在** | 数据记录不存在 | 该{业务对象}已被删除或不存在。[返回列表] | 该发票已被删除或不存在。[返回发票列表] | 不暗示是用户错误，给返回出口 |
| **操作引导型** | 重复操作/已处理 | 该{任务}已被处理，页面已刷新 | 该审批已处理完成，列表已更新 | 轻量告知，不打断，自动刷新 |
| **状态阻断型** | 状态不允许操作 | 暂无法{目标操作}。{业务对象}当前状态为{当前状态}，{操作}需在{允许状态}状态下进行 | 暂无法撤销。该流程当前状态为"已完成"，撤销仅可在"审批中"状态下进行 | 正向说明条件，不反向否定用户 |
| **系统兜底型** | 服务异常/网络超时 | 服务繁忙，请稍后重试 / 网络异常，操作未成功，请稍后重试 | 网络异常，操作未成功，请稍后重试 [重试] | 简短，不暴露技术细节 |
| **文件校验型** | 文件上传/导入失败 | 不支持此文件类型，请上传 {格式} 格式文件 | 不支持此文件类型，请上传 .xlsx .csv 格式文件 | 明确告知原因+正确做法 |
| **外部交互型** | 税局/第三方系统失败 | {外部系统}响应超时：{具体原因}。{引导操作} | 电子税局登录失败：密码错误，您还可尝试 4 次。请重新输入密码 | 保留外部系统的关键信息，包装为用户语言 |
| **流程占位型** | 流程中/处理中 | 该记录正在{流程名}中，暂不可操作 | 该员工正在转正审批中，暂不可发起新的转正申请 | 告知进行中的流程，不暗示错误 |

### 3.2 文案优化 Checklist

生成文案建议后，逐项检查：

- [ ] 是否去掉了技术术语（接口/远程服务/token/签名/参数）？
- [ ] 是否去掉了英文裸错误透传（Network Error/ECONNABORTED）？
- [ ] 字段名是否是用户理解的 label 而非数据库字段名（如"证件类型"而非"CERTYP"）？
- [ ] 是否避免了感叹号（!）和责备性词汇（请勿/不能/不允许）？
- [ ] 是否给出了明确的下���步操作（而非"请检查""请刷新"）？
- [ ] 复杂错误是否包含了 what + why + how？
- [ ] Toast 文案是否控制在 20 字以内？弹窗文案是否控制在 3 行以内？

## 4. 形式建议格式

### 4.1 决策依据

形式建议基于 `规则2-体验问题评估标准.md` 第 3 节"形式决策矩阵"。

### 4.2 输出格式

```
【形式优化建议】

当前问题：{当前用了什么形式，问题在哪}
建议方案：{推荐形式}。{选择该形式的具体理由}
分场景说明（如有多种场景）：
  - 首选：{场景A} → {推荐形式A}
  - 兜底：{场景B} → {推荐形式B}
依据：{引用规则2的形式决策矩阵中对应场景的判断标准}
预期效果：{形式变更后的体验改善}
```

### 4.3 形式建议 Checklist

- [ ] 推荐形式是否与错误的严重程度匹配？（阻断性 → 弹窗，字段级 → inline，终态告知 → Toast）
- [ ] 是否考虑了首选形式和兜底形式的区分？
- [ ] 是否说明了"是否保留弹窗"及其理由？

## 5. 时机建议格式

### 5.1 决策依据

时机建议基于 `规则2-体验问题评估标准.md` 第 2 节"时机等级定义"和"时机选择原则"。

### 5.2 输出格式

```
【时机优化建议】

当前问题：{当前在什么时机触发报错，问题在哪}
建议方案：{推荐时机等级}。{选择该时机的具体理由}
  - 首选：{时机X} — {具体触发点描述}
  - 兜底：{时机Y} — {什么边缘情况需要保留兜底}
判断依据：{能不能纯前端判断？需不需要后端数据？}
依据：{引用规则2的时机选择原则}
预期效果：{时机前置后的体验改善}
```

### 5.3 时机建议 Checklist

- [ ] 能否在页面加载时判断？ → 推荐时机 1
- [ ] 能否在输入时实时/失焦判断？ → 推荐时机 3/4
- [ ] 能否纯前端判断？ → 不依赖后端
- [ ] 只有必须后端/外部数据才推荐时机 7/8

## 7. 帮助中心文章生成规范

### 7.1 知识依赖

帮助中心文章的生成需要以下知识输入（第 1 节已声明）：

1. **报错场景上下文**（来自规则 1）：用户在什么模块、执行什么操作时遇到这个报错
2. **优化后的文案**（来自本文档第 3 节）：作为文章中引用的报错提示内容
3. **业务规则知识**（来自业务知识库）：为什么会有这个限制/校验/状态——用白话解释
4. **操作指引**（来自业务知识库）：正确的操作步骤是什么

### 7.2 文章结构模板

```markdown
# {标题：解决XXX问题}

## 适用场景
{什么情况下会遇到这个问题}

## 为什么会出现这个提示
{用白话解释业务规则，不暴露技术细节}

## 解决方法
### 步骤一：{操作名}
{具体操作步骤}

### 步骤二：{操作名}
{具体操作步骤}

{## 步骤N…}

## 常见问题
### Q: {问题1}
A: {回答1}

### Q: {问题2}
A: {回答2}
```

### 7.3 字段要求

| 字段 | 说明 | 示例 |
|------|------|------|
| **标题** | 以用户视角描述要解决的问题，控制在 15 字以内 | "提交发票时提示金额不一致" |
| **slug** | URL 友好标识，格式：`error-{错误码或场景标识}` | `error-invoice-amount-mismatch` |
| **适用场景** | 用"当你…"的第二人称句式 | "当你在财务模块提交发票，且含税金额与不含税金额+税额不等时" |
| **操作指引** | 每个步骤是一个动作，按顺序排列，含页面路径 | "1. 打开「财务管理-发票管理」；2. 点击「编辑」按钮…" |
| **FAQ** | 预判用户可能追问的问题 | "Q：我已经改了金额，还是报错怎么办？" |

### 7.4 生成 Checklist

- [ ] 标题是否以用户视角、用白话描述问题？
- [ ] "为什么"段落是否引用了业务知识库？是否标注了引用来源？
- [ ] 操作步骤是否按顺序排列？是否包含了具体的页面路径？
- [ ] FAQ 是否覆盖了用户最可能追问的 2-3 个问题？
- [ ] slug 是否唯一？
- [ ] 是否生成了可嵌入报错提示的短链接？（"查看帮助 →"）

## 8. 优化建议质量自检清单

生成完整优化建议后，逐项检查：

- **文案**：无技术术语、无英文裸错误、字段名用户化、无责备语气、有明确下一步
- **形式**：与严重度匹配、区分首选兜底、说明了是否保留弹窗
- **时机**：尽量前置、说明了能否纯前端判断、保留了兜底时机
- **交互**：有出口、数据不丢失、有兜底路径
- **帮助中心文章**：有业务知识引用、操作步骤可执行、FAQ 覆盖常见追问
