## 1. 度量指标体系

### 1.1 指标分类

| 指标类别 | 指标 | 说明 | 计算方式 |
|---------|------|------|---------|
| **报错压降** | 报错压降率 | 优化后报错次数相对优化前的下降比例 | (优化前次数 - 优化后次数) / 优化前次数 × 100% |
| **任务完成** | 任务一次性完成率 | 用户首次操作即成功完成（未经报错打断）的比例 | 一次成功的会话数 / 总会话数 × 100% |
| **任务完成** | 任务完成率 | 用户最终完成任务的比例 | 成功的会话数 / 总会话数 × 100% |
| **任务完成** | 任务完成时长（中位数）| 从开始操作到完成任务的中位时间 | 排序后取 P50 |
| **效率** | GOMS 步骤数减少 | 优化后用户完成操作的步骤数减少量 | 优化前步骤数 - 优化后步骤数 |
| **效率** | 关键步骤成功率 | 特定步骤（如提交/保存）的成功比例 | 成功次数 / 总操作次数 × 100% |
| **上报** | 上报项成功率 | 批量上报/导入的整体成功率 | 成功的上报任务数 / 总上报任务数 × 100% |
| **引导** | 引导点击率 | 优化后新增的引导入口（联系管理员/查看帮助/前往设置）被点击的比例 | 点击次数 / 展示次数 × 100% |
| **客服** | 客服咨询量 | 与特定报错相关的客服咨询/工单数量变化 | 优化前咨询量 - 优化后咨询量 |
| **满意度** | 满意度得分 | 用户对特定操作/模块的满意度评分变化 | 优化后得分 - 优化前得分 |
| **活跃** | 月活转深度月活 | 月度活跃用户转化为深度使用用户的比例变化 | 转化率变化 |
| **留存** | 深度月活转存续 | 深度使用用户的持续使用情况 | 留存率变化 |

### 1.2 指标与优化方向的对应

| 优化方向 | 优先关注的指标 | 说明 |
|---------|-------------|------|
| 形式优化（弹窗→轻量）| 报错压降率、GOMS 步骤数减少 | 弹窗阻断被消除后的直接效果 |
| 时机优化（提交后→输入时/页面加载时）| 任务一次性完成率、任务完成时长 | 校验前置使用户提交前就知道问题 |
| 文案优化 | 客服咨询量、引导点击率、满意度得分 | 用户看懂文案后不需问客服 |
| 业务规则优化 | 关键步骤成功率、上报项成功率 | 减少因规则理解不到位导致的操作失败 |

## 3. 回检方案规范

### 3.1 回检周期定义

| 优化类型 | 首次回检时间 | 二次回检时间 | 说明 |
|---------|------------|------------|------|
| 文案路径（仅改文案）| 发布后 3 天 | 发布后 14 天 | 文案变更即时生效，短期即可观察 |
| 开发路径（前端修改）| 上线后 7 天 | 上线后 30 天 | 需等灰度/全量覆盖 |
| 开发路径（后端/多系统联动）| 上线后 14 天 | 上线后 30 天 | 需完整业务周期覆盖 |

### 3.2 数据对比规范

```
回检数据 = {
    基线期: 优化前 N 天的数据窗口,
    观察期: 优化后 N 天的数据窗口
}

要求：
- 基线期和观察期窗口长度相等
- 窗口内应覆盖完整的业务周期（如包含月末发薪/申报高峰）
- 排除已知的外部事件影响（如系统故障、节假日）
```

### 3.3 成效判定标准

| 判定结果 | 条件 |
|---------|------|
| **改善** | 核心度量指标显著正向变化（>10%），无指标恶化 |
| **无变化** | 核心度量指标变化 <10%，或正向和负向变化混合 |
| **恶化** | 核心度量指标显著负向变化（<-10%），或有多个指标恶化 |

## 4. 埋点方案模板（埋点缺失时）

*本节为框架。当优化条目缺乏回检所需的埋点数据时，按以下模板输出埋点方案：*

```markdown
## 埋点方案：{报错场景名称}

### 当前缺失的数据
- {缺失的指标 1}：无法获取，因为 {原因}
- {缺失的指标 2}：无法获取，因为 {原因}

### 建议新增的埋点事件

#### 事件 1：{事件名称}
- **触发时机**：{什么时候上报}
- **事件参数**：{参数名1}（{类型}，{说明}）、{参数名2}（{类型}，{说明}）

#### 事件 2：{事件名称}
- ...

### 埋点上线前替代验证方式
在埋点上线前，可用以下方式近似评估：
- {替代方式 1}
- {替代方式 2}

### 埋点需求优先级
{P0/P1/P2} — {理由}
```

### 需定义的埋点事件类型（模板）

| 事件类型 | 事件名 | 触发时机 | 关键参数 |
|---------|--------|---------|---------|
| 报错曝光 | `error_display` | 报错提示展示给用户时 | error_code, form_type（弹窗/Toast/inline…）, page_route |
| 报错关闭 | `error_dismiss` | 用户关闭报错提示时 | error_code, dismiss_action（关闭/点击引导/点击帮助）|
| 操作成功 | `task_success` | 用户完成目标操作时 | task_type, step_count（操作步骤数）, duration（耗时）|
| 操作放弃 | `task_abandon` | 用户中途放弃时 | task_type, abandon_step（在哪一步放弃）, last_error_code |
| 引导点击 | `guide_click` | 用户点击报错中的引导入口时 | guide_type（联系管理员/查看帮助/前往设置/重试）, error_code |
| 按钮置灰曝光 | `button_disabled_view` | 置灰按钮被用户视野扫描到 | button_name, disable_reason, page_route |
