## 1. 分类框架

### 分类维度

| 维度 | 说明 | 示例 |
|------|------|------|
| 大类 | 报错的顶层分类，按错误性质划分 | 权限类、系统异常类、数据校验类、业务状态类、业务规则限制类 |
| 小类 | 大类下的细分场景 | 操作权限不足、参数为空校验、状态不允许操作… |
| 任务类型 | 用户触发报错时正在执行的操作 | 提交表单、发起审批、导入文件、查看数据… |
| 校验逻辑 | 触发报错的校验规则 | 必填校验、存在性校验、状态机校验、格式校验… |
| 报错原因 | 校验不通过的具体原因 | 字段为空、数据已被删除、当前状态不允许操作… |
| 涉及业务模块 | 报错发生的业务领域 | 薪资计算、考勤管理、财务凭证、发票税务… |

### 大类定义

| 大类 | 定义 | 典型特征 |
|------|------|---------|
| **权限类** | 用户身份或授权不满足操作要求 | 与用户角色/权限码/数据范围相关 |
| **系统异常类** | 系统侧的技术问题导致操作失败 | 与网络、服务、第三方调用相关，用户无法直接解决 |
| **数据校验类** | 用户输入或提交的数据不符合规则 | 与字段值、格式、文件相关，用户可以通过修改数据解决 |
| **业务状态类** | 被操作的数据当前状态不允许执行目标操作 | 与数据生命周期状态相关（已删除/已处理/已锁定…） |
| **业务规则限制类** | 业务模块特有的规则限制 | 与具体业务领域规则相关（考勤/薪资/财务/发票…） |

## 2. 大类 × 小类分类表

### 2.1 权限类

| 小类 | 任务类型 | 校验逻辑 | 报错原因 | 出现频次 |
|------|---------|---------|---------|---------|
| 操作权限不足 | 用户执行某功能操作（查看/编辑/删除/发起流程等） | 后端校验当前用户是否拥有该功能/接口的操作权限码 | 用户未分配该功能权限，或权限配置缺失 | ~5,000+ |
| 数据权限不足 | 用户查看/操作特定数据范围（如某部门、某账套） | 校验用户是否拥有该数据范围（部门/组织/账套等）的查看权限 | 用户未被授予该数据范围的数据权限 | ~444 |
| 登录/会话失效 | 任何需要登录态的操作 | 校验 token/session 是否有效、是否过期 | 未登录、token 为空、签名过期、session 失效 | ~143 |

### 2.2 系统异常类

| 小类 | 任务类型 | 校验逻辑 | 报错原因 | 出现频次 |
|------|---------|---------|---------|---------|
| 网络/超时错误 | 任何涉及网络请求的操作 | 前端请求是否成功到达后端并返回 | 网络断开、请求超时(120s)、网关超时(504)、服务器错误(500/502) | ~8,061 |
| 服务端通用异常 | 任何后端操作 | 后端服务是否正常响应 | 后端服务异常、系统繁忙、服务维护中 | ~2,968 |
| 远程调用/接口异常 | 调用第三方/外部/微服务接口 | RPC/HTTP 调用是否成功返回 | 远程服务超时、不可用、返回异常 | ~187 |

### 2.3 数据校验类

| 小类 | 任务类型 | 校验逻辑 | 报错原因 | 出现频次 |
|------|---------|---------|---------|---------|
| 参数为空校验 | 表单提交、数据保存 | 后端/前端校验必填字段是否为空 | 必填字段未填写 | ~968 |
| 参数格式/内容错误 | 表单提交、数据导入 | 校验字段值是否符合格式要求 | 日期格式错误、编码规则不符、字段超长等 | ~171 |
| 唯一性/重复校验 | 新增/创建数据 | 校验名称/编码/编号是否与已有数据重复 | 提交的数据与已有数据重复 | ~745 |
| 文件上传校验 | 文件上传/导入 | 校验文件格式、大小、名称合法性、内容解析 | 文件格式不支持、文件名含非法字符、文件过大、Excel 解析失败 | ~195 |
| 金额/数值校验 | 财务开票、薪资计算、凭证录入 | 金额勾稽关系校验、数值转换校验 | 不含税金额+税额≠含税金额、非数值型数据、金额为 0 等 | ~97 |

### 2.4 业务状态类

| 小类 | 任务类型 | 校验逻辑 | 报错原因 | 出现频次 |
|------|---------|---------|---------|---------|
| 数据/记录不存在 | 查看/操作某条具体数据记录 | 根据 ID 查询数据库记录是否存在 | 数据已被删除、作废、或从未创建 | ~1,097 |
| 重复操作/已处理 | 审批、任务处理、确认操作 | 校验当前数据是否已处于「已处理」终态 | 任务已被他人处理、流程已结束 | ~238 |
| 状态不允许操作 | 对某条记录执行状态变更操作 | 校验当前状态是否允许执行目标操作（状态机校验） | 当前状态不在允许操作的状态列表中 | ~93 |
| 流程中/处理中 | 对已在流程中的数据发起新操作 | 校验是否已有进行中的流程/任务 | 数据处于审批中、计算中、处理中，需等待完成 | ~221 |
| 已锁定/已冻结/已结账 | 修改/编辑已锁定数据 | 校验数据是否处于锁定/结账/冻结状态 | 数据被锁定不可修改 | ~131 |

### 2.5 业务规则限制类

| 小类 | 任务类型 | 校验逻辑 | 报错原因 | 出现频次 |
|------|---------|---------|---------|---------|
| 考勤相关 | 考勤打卡、排班、请假、加班、调店/借调 | 考勤周期设置、排班信息、时间冲突、员工考勤组校验 | 考勤周期未设置、排班不存在、时间冲突、不在考勤组 | ~728 |
| 薪资/算税相关 | 薪资计算、个税申报、工资单查看 | 薪资组状态、算税状态、数据权限校验 | 薪资组锁定、正在算税中、个税已申报 | ~658 |
| 财务凭证相关 | 凭证录入、账套管理、科目设置 | 凭证编号唯一性、金额非 0、账套存在性、结账状态校验 | 凭证重复、金额为 0、账套不存在、期间已结账 | ~817 |
| 发票/税务相关 | 发票开具、税局登录、发票查询 | 发票信息完整性、金额勾稽、税局接口校验 | 发票信息不匹配、税局登录失败、税号不支持 | ~3,965 |

## 3. 分类决策规则（框架）

> 以下为分类决策的核心逻辑，给一条新报错时，按此顺序判断归属。

### 决策流程

```
Step 1: 是否是系统技术问题？
  ├── 含技术裸错误（Network Error / timeout / 5xx / ECONNABORTED…）→ 系统异常类
  ├── 含 token / session / 签名 / 登录态 关键词 → 权限类·登录/会话失效
  └── 含远程服务 / 接口 / RPC 关键词 → 系统异常类·远程调用异常
        ↓ 否
Step 2: 是否涉及用户身份/授权？
  ├── 含权限 / 无访问 / 管理员 / 授权 关键词 → 权限类
  └── 细分：涉及具体数据范围（部门/账套/区域）→ 数据权限不足
            涉及功能操作 → 操作权限不足
        ↓ 否
Step 3: 是否涉及用户输入的数据校验？
  ├── 含 不能为空 / 必填 → 数据校验类·参数为空
  ├── 含 格式不正确 / 长度超过 / 不合法 → 数据校验类·格式/内容
  ├── 含 已存在 / 重复 → 数据校验类·唯一性
  ├── 含 文件 / 上传 / 导入 / 解析失败 → 数据校验类·文件上传
  └── 含 金额 / 税额 / 数值 / 勾稽 → 数据校验类·金额/数值
        ↓ 否
Step 4: 是否涉及数据生命周期状态？
  ├── 含 不存在 / 已被删除 / 未找到 → 业务状态类·数据不存在
  ├── 含 已处理 / 请勿重复 / 已结束 → 业务状态类·重复操作
  ├── 含 锁定 / 结账 / 冻结 / 不可修改 → 业务状态类·已锁定
  ├── 含 流程中 / 审批中 / 处理中 / 进行中 → 业务状态类·流程中
  └── 含 状态 / 不能 / 不允许 操作 → 业务状态类·状态不允许
        ↓ 否
Step 5: 是否涉及特定业务领域规则？
  ├── 含 考勤 / 排班 / 打卡 / 请假 / 调店 → 业务规则限制类·考勤
  ├── 含 薪资 / 算税 / 个税 / 工资单 → 业务规则限制类·薪资
  ├── 含 发票 / 税局 / 税号 / 开票 → 业务规则限制类·发票
  └── 含 凭证 / 账套 / 科目 / 借贷 → 业务规则限制类·财务
        ↓ 未命中
      标记为「未分类」，人工标注后追加到种子数据
```

### 边界 case 处理规则（待补充）

- [ ] 一条报错同时匹配多个大类的判定条件时，按上述决策顺序（Step 1→5）的优先级，先命中先归类
- [ ] 一条报错在大类内同时匹配多个小类时，以报错文案的主语义（不是附带信息）为判定依据
- [ ] 含业务模块关键词但实质是数据校验的（如"发票金额不能为空"），优先归入数据校验类
- [ ] 新增业务模块时如何扩展分类表？（待定义）

## 4. 种子数据与渐进维护

### 维护机制

```
新报错进入 → AI 按决策规则（第 3 节）归类
                ↓
        人工审核确认 / 修正归类
                ↓
        修正结果追加到种子数据（第 4.2 节）
                ↓
        同类别样本积累 → AI 归类准确率逐步提升
```

### 种子数据源

| 来源 | 说明 |
