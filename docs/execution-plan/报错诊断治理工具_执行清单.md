# 《报错诊断治理工具》执行清单

> 依据：`__# 《报错诊断治理工具》Goal Definition.md`
>
> 新版推进原则：本工具落地不采用“一次性完整自动化”的方式，而采用“最小诊断链路 + 轻量运行控制 + 人工复核闭环 + 上线回检准备 + 逐步扩展自动化”的方式推进。前期优先保证诊断准确性、证据可追溯、人工结论可回写、异常条目可分流；中期补齐优化方案、文案发布包、开发排期跟进和上线登记；后期再建设自动回检、Hook、Cron、API 调用、批量调度和月报生成等生产级 Harness 能力。

---

## 一、规则文档边界说明

| 规则文档 | 回答的问题 | 关注什么 |
|----------|-----------|---------|
| DOC-01：报错特征分类体系 | “这是什么报错” | 报错的**身份属性**，包括类别、任务、校验、原因、模块 |
| DOC-02：体验问题评估标准 | “这个报错体验好不好” | 报错的**呈现质量**，包括时机、形式、文案、交互 |
| DOC-03：实施路径判定规则 | “这个问题应该怎么修” | 纯文案、配置化、前端交互、后端规则逻辑四类路径 |
| DOC-04：优先级评分规则 | “这个问题值不值得优先修” | 旅程影响、体验违规、客户影响、报错规模、修复可行性 |
| DOC-05：成效预估与可信度规则 | “预计能带来什么收益，可信度如何” | 成效预估区间、可信度、依据来源、不可验证风险 |
| DOC-06：异常分流与问题池规则 | “跑不通或证据不足时怎么办” | 缺字段、低置信、无证据、规则冲突、埋点缺口等分流 |
| DOC-07：人工复核结论与状态流转规则 | “人工确认后怎么归档和推进” | 复核结论枚举、台账回写、问题池流转、规则反哺 |
| DOC-08：优化建议生成规范 | “优化建议怎么交付” | 交互、时机、形式、文案、帮助中心文章、优化前后对比 |
| DOC-09：回检指标与埋点方案标准 | “后续怎么验证成效” | 回检指标、基线窗口、观察窗口、埋点补齐方案 |
| DOC-10：上线与回检准备登记规则 | “自动回检前需要补齐什么” | 上线时间、上线范围、上线版本、埋点口径、回检就绪检查 |

**报错形式（弹窗 / Toast / 行内提示 / 占位 / banner 等）属于 DOC-02 的评估对象，不属于 DOC-01 的身份属性。**

## 目标

原执行清单中“数据源字段映射表”被放在规则 7，但它实际上是整个工具能否跑通的输入契约，应前置为 Phase 0。

## 产出

```text
DOC-00 数据源盘点与输入输出契约.md
```

|------|---------|
| 输入报错表 | 必填字段、可选字段、字段别名、缺失处理 |
| 去重汇总表 | 错误码、URL、页面路由、报错类型、页面报错次数、分区日期、月均报错次数 |

| 工单源 | 数据路径、关联键、历史治理记录匹配规则 |
| 埋点源 | 报错指标、旅程指标、任务完成指标、API 获取方式 |

## 验收标准

```text
- 明确字段缺失时是降级处理，还是进入“待补充信息池”。
- 明确输出诊断报告、复核卡、台账记录和问题池记录的最小字段。
```

# Phase 3：SKILL-01-MVP + HARNESS-MVP + 人工复核闭环

## 目标

用 5 条真实报错跑通最小链路，但不是只生成报告，而是形成：

```text
诊断 → 人工复核 → 结论回写 → 状态分流 → 规则修正候选
```

## 最小链路

```text
单条真实报错输入
↓
输入字段标准化
↓
报错特征提取
↓
本地规则 / 知识库匹配
↓
体验问题评估
↓
优先级评分
↓
成效预估可信度判断
↓
实施路径建议
↓
综合诊断报告
↓
人工复核卡
↓
人工填写结论
↓
状态分流与台账回写
```

## HARNESS-MVP 能力范围

| 能力 | 说明 |
|------|------|
| 运行记录 | 记录每条报错是否成功跑完 |
| 步骤状态 | 标记输入、分类、检索、评估、报告是否成功 |
| 异常捕获 | 捕获缺字段、低置信、无证据、规则冲突 |
| 问题池分流 | 自动进入待补充信息池、规则修正池、埋点缺口池等 |
| 人工复核卡 | 生成可供设计 / 产品 / 运营 / 研发确认的复核卡 |
| 人工结论回写 | 将人工结论写入治理台账 |
| 规则修正候选 | 对评估不准确条目生成规则修正建议 |
| 归档准备 | 将成功 / 失败 / 无需优化条目归档到对应池 |

## 人工复核结论枚举

| 人工结论 | 含义 | 后续状态 |
|----------|------|----------|
| 评估准确，进入治理 | AI 判断基本正确，问题成立 | 治理候选池 |
| 评估基本准确，需调整建议 | 问题成立，但建议、优先级或路径需调整 | 待调整建议 |
| 评估不准确 | 分类、场景、体验判断错误 | 规则修正池 |
| 条目暂未复现 | 当前无法复现，不进入治理 | 暂未复现池 |
| 条目无需优化 | 报错合理，或为正常业务拦截 | 无需优化归档 |
| 需补充信息 | 缺少截图、路径、客户反馈、数据证据 | 待补充信息池 |
| 需产品确认 | 涉及业务规则判断 | 产品确认池 |
| 需研发确认 | 涉及技术实现或接口逻辑 | 研发确认池 |
| 需补充埋点 | 当前无法验证影响或无法回检 | 埋点缺口池 |

## 验收标准

| 验收项 | 标准 |
|--------|------|
| 真实样本 | 至少 5 条真实报错 |
| 报告生成 | 每条都能生成综合诊断报告 |
| 复核卡生成 | 每条都能生成可填写的人工复核卡 |
| 证据可追溯 | 报告中能追溯规则依据和数据来源 |
| 异常分流 | 缺字段、低置信、无证据条目能进入对应问题池 |
| 人工结论回写 | 人工结论能写入治理台账 |
| 规则修正候选 | 对“评估不准确”条目生成修正候选 |

# Phase 4：小批量验证与规则修正

## 目标

从 5 条单条验证扩展到 20-30 条真实报错，验证批量一致性、复核一致率和规则修正闭环。

## 做什么

| 项目 | 内容 |
|------|------|
| 样本选择 | 选取 20-30 条真实报错，覆盖不同大类、不同业务模块、不同严重度 |
| 运行方式 | 批量运行 SKILL-01-MVP |
| 复核方式 | 人工逐条复核诊断结论、路径判定、优先级、优化方向 |
| 规则修正 | 对评估不准确条目生成规则修正候选 |
| 种子数据更新 | 经确认的分类修正结果追加到种子数据 |

## 验收标准

| 验收项 | 建议标准 |
|--------|----------|
| 特征提取准确率 | 与人工标注一致率 ≥ 85% |
| 体验问题判断准确率 | 与人工复核一致率 ≥ 80% |
| 路径判定准确率 | 与人工复核一致率 ≥ 80% |
| 多源证据有效率 | Top 5 证据中至少 3 条有效 |
| 报告完整率 | 必填字段完整率 ≥ 95% |
| 异常分流准确率 | 异常条目能进入正确问题池 |
| 人工复核回写成功率 | 100% 写入台账 |
| 规则修正候选生成率 | 对“评估不准确”条目 100% 生成修正候选 |

## 依赖

Phase 3 通过。

## 阻断性

Phase 4 通过后，才建议进入 SKILL-02 和后续交付型 Skill。

# Phase 8：上线与回检准备登记

## 目标

在自动回检前，由人工补充或确认上线信息、回检窗口、埋点口径、指标口径和数据获取方式，确保后续自动回检有明确的时间边界和数据依据。

## 为什么必须增加

自动回检依赖两个前置条件：

```text
1. 上线时间 / 上线范围 / 上线版本是否明确
2. 埋点口径 / 埋点文档 / 指标映射是否明确
```

如果缺少这两类信息，系统即使能调用 API，也无法判断：

```text
- 从哪一天开始算上线后一个月
- 回检数据是否覆盖正确用户和页面
- API 拉到的埋点是否仍然是当前优化对应的指标
- 新增埋点或埋点变更后，指标口径是否还能沿用
```

## 适用对象

```text
1. 已进入开发排期并完成上线的报错条目
2. 通过文案平台 / 配置平台发布完成的报错条目
```

## 输入

```text
- 治理条目 ID
- 报错 ID / 错误码
- 优化类型：文案 / 配置 / 前端交互 / 后端规则
- 上线时间
- 上线版本
- 上线范围
- 是否灰度发布
- 是否全量发布
- 影响页面 / 路由
- 关联埋点事件
- 埋点文档路径
- 指标口径说明
- API 数据获取方式
```

## 输出

```text
上线与回检准备记录：
- 是否具备回检条件
- 推荐回检开始时间
- 推荐首次回检周期
- 是否需要延长观察周期
- 是否需要人工补充埋点文档
- 是否进入“已上线待回检池”
- 是否进入“待补充上线信息池”
- 是否进入“埋点口径待确认池”
```

# Phase 9：SKILL-04 回检分析 Skill

## 目标

对已上线且通过回检就绪检查的条目进行成效验证。

## 输入

```text
- 治理条目 ID
- 上线时间
- 上线范围
- 上线版本
- 优化前基线数据
- 优化后观察数据
- 回检指标
- 回检周期
- 埋点状态
- 埋点文档路径
```

## 输出

```text
回检分析报告：
- 是否达到预期
- 主指标变化
- 辅助指标变化
- 是否存在归因风险
- 成效可信度
- 是否需要延长观察周期
- 是否需要复诊
- 成功案例 / 踩坑记录草稿
```

## 回检周期建议

| 场景 | 回检周期 |
|------|----------|
| 高频报错、流量稳定 | 上线后 30 天首次回检 |
| 低频报错、样本不足 | 上线后 60 天回检 |
| 灰度发布 | 从全量发布时间开始计算正式回检周期 |
| 版本分批上线 | 按主要上线范围的全量时间计算 |
| 一个月无明显效果但样本不足 | 延长至 60 / 90 天二次回检 |
| 一个月无明显效果且样本充足 | 进入复诊分析 |
| 关键旅程问题 | 可增加 7 天短周期观察 + 30 天正式回检 |

## 验收标准

| 验收项 | 标准 |
|--------|------|
| 数据获取 | 能根据上线登记和埋点口径拉取数据 |
| 指标对比 | 能输出优化前后主指标和辅助指标变化 |
| 归因说明 | 能说明是否存在流量、版本、样本不足等归因风险 |
| 延长观察 | 样本不足时能进入延长观察周期池 |
| 复诊分析 | 无明显效果且样本充足时能生成复诊建议 |
| 归档候选 | 能生成成功案例或踩坑记录草稿 |

# Phase 10：HARNESS-PROD 生产级自动化

## 目标

当单条、小批量、人工复核、发布包、上线登记、回检分析都稳定后，再进入生产级自动化。

## 模块

| 模块 | 内容 |
|------|------|
| HARNESS-01 新数据到达触发 | Hook 监听目录，新文件到达后自动触发过滤与诊断 |
| HARNESS-02 批量任务调度 | 分批运行、失败重试、运行日志 |
| HARNESS-03 权限配置 | 数据读取、台账写入、平台调用、运行权限、人工确认权限 |
| HARNESS-04 回检周期触发 | Cron 扫描已上线且达到回检周期的条目 |
| HARNESS-05 问题池维护 | 自动更新暂未复现池、待补充池、埋点缺口池、上线信息池 |
| HARNESS-06 月报生成 | 汇总治理规模、流程转化效率、成效、问题池情况 |
| HARNESS-07 知识库归档控制 | 待确认经验 → 人工确认 → 正式知识库 |

## HARNESS-03 权限配置说明

| 权限类型 | 内容 |
|----------|------|
| 数据读取权限 | 报错表、客户反馈、工单、埋点数据、知识库 |
| 台账写入权限 | 诊断报告、复核结论、问题池、上线登记、回检结果 |
| 平台调用权限 | 文案治理平台 API、测试环境发布、生产发布、回滚 |
| 运行权限 | 监听目录、定时任务、批量脚本、文件读写 |
| 人工确认权限 | 设计 / 产品 / 运营 / 研发 / 项目负责人各自可确认的节点 |

## 修改后的 HARNESS-04

| 项目 | 内容 |
|------|------|
| 做什么 | Cron 每周扫描“已上线待回检池”，判断条目是否满足回检条件 |
| 前置条件 | 已录入实际上线时间、上线范围、上线版本、回检周期、主指标、埋点口径 |
| 自动动作 | 达到回检时间后，调用 SKILL-04 拉取数据并生成回检报告 |
| 异常分流 | 缺上线时间 → 待补充上线信息池；缺埋点口径 → 埋点口径待确认池；数据不足 → 延长观察周期 |
| 依赖 | 上线登记表、埋点口径确认表、DOC-09、DOC-10、SKILL-04 |

# 三、问题池体系

| 问题池 | 进入条件 | 后续动作 |
|--------|----------|----------|
| 待评估池 | 新增高频报错，尚未诊断 | 进入 SKILL-01 |
| 治理候选池 | AI 诊断准确，人工确认需治理 | 进入方案设计 / 发布包 |
| 暂未复现池 | 人工暂时无法复现 | 保留观察，定期复核 |
| 无需优化归档 | 报错合理或为正常业务拦截 | 归档，不进入治理 |
| 待补充信息池 | 缺少关键字段、截图、操作路径 | 补充后重新诊断 |
| 低置信诊断池 | AI 分类或评估置信度低 | 人工复核 / 规则修正 |
| 规则修正池 | 人工判定 AI 评估不准确 | 生成规则修正候选 |
| 埋点缺口池 | 无法判断影响或无法回检 | 生成埋点补齐方案 |
| 平台能力缺口池 | 建议合理但平台不支持发布 / 配置 | 进入工具能力建设 |
| 已上线待回检池 | 已完成优化并补充上线信息 | 等待回检 |
| 待补充上线信息池 | 缺少实际上线时间、上线范围、上线版本 | 人工补充上线信息 |
| 埋点口径待确认池 | 埋点新增、变更或口径不确定 | 人工补充埋点文档 |
| 数据权限待确认池 | API 或数据文件无法访问 | 补充权限或替代数据源 |
| 延长观察周期池 | 首次回检无明显效果但样本不足 | 60 / 90 天二次回检 |
| 成功案例池 | 回检有效 | 进入待确认知识库 |
| 踩坑记录池 | 回检无效或误判 | 进入待确认知识库 / 复诊 |
