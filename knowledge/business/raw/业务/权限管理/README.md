# permission

## 这是什么

这是权限业务知识库的结构化目录，用于把权限域知识拆成可维护、可迁移、可复用的模块。

## 怎么用

- 先读 `00_领域概述.md` 了解权限域目标与边界
- 再读 `10_能力地图.md`、`11_任务场景.md`、`12_查询与配置路径.md` 理解业务承载
- 再读 `20` 到 `25` 号文件理解规则、来源、原因码、治理与审计
- 最后读 `30` 到 `42` 号文件理解体验转译与蓝图交接要求

## 阅读顺序

1. 领域总览层
2. 业务能力与场景层
3. 决策与规则层
4. 体验转译层
5. 蓝图消费层

## 维护原则

- 只记录业务语义、规则合同、责任边界与风险约束
- 不在本目录中写具体页面、组件、视觉方案
- 尽量复用已有概念，避免新增权限概念
- 新知识优先落到对应编号模块，不回写为大一统长文

## 迁移原则

- 已有知识按迁移规则拆分落盘
- 未覆盖内容先保留骨架，再逐步补齐
- 后续其他业务域可复用同一编号体系进行复制
